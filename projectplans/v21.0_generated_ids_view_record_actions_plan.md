# v21.0 — Generated IDs: View Record Actions

## Status: COMPLETE

## Background

The **Generated IDs** list (`/system/id-generated-list`) is currently read-only: it shows `display_id`, `target_table`, `record_id` (UUID), and `created_at`, but provides no way to open the underlying record in its native admin screen.

Admins expect a **View** (read) action that deep-links to the correct detail/form page using `target_table` + `record_id` (or display ID). This mirrors how list pages elsewhere navigate with `navId(displayIdMap, uuid)` and `?id=` query params resolved by `useDisplayId`.

Recent work added **code reference search** on Generated IDs (`displayIdSearch.js`) and clickable preview segments on the ID rule form. This plan adds the complementary **navigation out** from generated ID rows to source records.

Cross-reference: `projectplans/v2.0_id_generation_plan.md` (Target Tables by System — which tables have detail pages vs list-only).

## Goals

- Add an **Actions** column to Generated IDs with a **View** action when a mapped admin detail/read route exists.
- Resolve routes centrally from `target_table` (normalized) so new mappings are one registry entry, not scattered UI logic.
- Pass **display ID** in URLs when available (detail pages already accept UUID or display ID via `useDisplayId`).
- Show explicit **View unavailable** state (with reason) for tables without an admin detail screen — especially after bulk rule seed (v148–v150) where hundreds of tables have IDs but no dedicated UI.
- Document how to register new view routes when admin screens are added.

## Non-goals

- Building new detail pages for every bulk-seeded table (e.g. full `public.projects` detail) — tracked as follow-ups per table.
- **Edit** / **Delete** actions from Generated IDs (View/read only in v21).
- Links to the platform (non-admin) app — admin console routes only.
- DB-driven route registry in v21 (static shared registry first; SQL registry optional later).

## Phase 1 — Central route registry + View action (core) ✅

### 1.1 Shared resolver ✅

**New file:** `packages/shared/src/generatedIdRecordRoutes.js`

```text
resolveGeneratedIdRecordView({ target_table, record_id, display_id })
  → { available, href, label, reason, actionType }
```

**Behaviour:**

- Normalize `target_table` via `normalizeTargetTable()` from `idGenerationRuleUtils.js` (handles `public.foo` vs legacy bare `foo`).
- Look up a static registry keyed by normalized table name.
- Build `href` as `{path}?{query}` using `display_id` when present, else `record_id` (detail pages resolve both).
- Return `available: false` + human-readable `reason` when unmapped.

**Export** from `packages/shared/src/index.js`.

### 1.2 Initial route mappings ✅

Wire tables that **already have** admin detail/read pages:

| `target_table` | Route | Query params | Label |
|----------------|-------|--------------|-------|
| `public.users` | `/users/user-detail` | `id` | View user |
| `public.accounts` | `/users/org-detail` | `id` | View organisation |
| `public.platform_subscriptions` | `/subscriptions/subscription-detail` | `id`, `system=platform` | View subscription |
| `sim.scenarios` | `/simulator/sim-scenario-detail` | `id` | View scenario |
| `admin.admin_users` | `/admin-mgmt/admin-user-edit` | `id` | View admin user |
| `admin.support_tickets` | `/support/support-ticket-detail` | `id` | View ticket |
| `admin.id_generation_rules` | `/system/id-generation-rule-form` | `id` | View ID rule |

**Subscription `system` param:**

- `SubscriptionDetailPage` requires `?system=platform|simulator`.
- **Default:** `system=platform` for `public.platform_subscriptions`.
- **Enhancement (same phase if low cost):** optional lookup of subscription row to set `system` from stored data when a distinguishing column exists; otherwise keep default.

**Unmapped example:** `public.projects` — IDs exist (`PRJ-*`) but `PlatformProjectsOverviewPage` is list-only with no row detail route (noted in v2.0 plan). Show **View unavailable** until a project detail page exists.

### 1.3 Generated IDs UI ✅

**File:** `modules/system/src/pages/GeneratedIDsPage.jsx`

- Add **Actions** column (rightmost).
- **View** — `Link` / button when `available === true`; same-tab navigation (consistent with admin).
- **Unavailable** — muted text + tooltip with `reason` (e.g. *No admin detail page for public.activity_logs*).
- Optional secondary: **Copy admin link** when route is available.

Preserve existing: code reference column, display ID split/highlight, table filter, URL params (`?search=`, `?table=`).

### 1.4 Documentation ✅

**File:** `modules/system/docs/ID_Generation_Capacity_Guide.md` (or new short guide)

- Section: **Adding a Generated ID view route** — register entry in `generatedIdRecordRoutes.js`, test View from Generated IDs list.
- Update `modules/system/docs/README.md` index if a new guide is added.
- Register in `admin.documentation_guides` via companion seed SQL if a new standalone guide is created (per repo convention).

**No SQL migration required for Phase 1.**

## Phase 2 — List fallbacks for list-only admin pages (optional) ✅

For tables with **list-only** admin screens and no detail route:

| `target_table` | Fallback route | Behaviour |
|----------------|----------------|-----------|
| `sim.certificates` | `/simulator/sim-certificate-admin` | Open list with `?search={display_id}` |
| `sim.learning_paths` | `/simulator/sim-learning-path-admin` | Same |
| `sim.npcs` | `/simulator/sim-n-p-c-admin` | Same |
| `sim.leaderboard_entries` | `/simulator/sim-leaderboard-admin` | Same |
| `public.projects` | `/platform/platform-projects-overview` | Open list with search (until detail page exists) |

- Label: **Open in list** (distinct from **View**).
- Requires list pages to honour `?search=` on load (add if missing).

**Decision:** Phase 1 + Phase 2 shipped together.

## Phase 3 — Generic read-only inspector (optional, later) — DEFERRED

If unmapped tables are too common after bulk seed:

- New page: `/system/generated-id-record-inspector?table=…&id=…`
- SECURITY DEFINER RPC: fetch row JSON by schema-qualified table + UUID (permission-gated, read-only).
- Fallback **View** when no dedicated form exists.

Defer unless product requires universal coverage before per-table detail pages exist.
