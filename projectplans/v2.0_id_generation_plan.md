## Context

The admin panel currently uses raw UUIDs everywhere — in URLs, list views, and detail pages across all three systems (Admin, Platform, Simulator). This makes records hard to identify at a glance (e.g., `/users/user-detail?id=3f8a92d1-...`). Admins need to configure human-readable ID formats per database table (e.g., `USR-AB1234`), with these display IDs shown in URLs instead of UUIDs.

The system spans **three database schemas**:
- **`admin`** — admin panel tables (admin_users, support_tickets, feature_flags, etc.)
- **`public`** — platform tables (users, accounts, projects, platform_subscriptions, etc.)
- **`sim`** — simulator tables (scenarios, certificates, leaderboard_entries, learning_paths, npcs, etc.)

All `target_table` references use **schema-qualified names** (e.g., `public.users`, `sim.scenarios`, `admin.admin_users`) to avoid ambiguity across schemas.

The reference image shows a "Create ID Generation Rule" form with: Database Table dropdown, Prefix, Suffix, Letter Case, Number of Letters, Number of Digits, Seed Value, Active toggle, and a live ID Format Preview (`[L2D4] Example: AB1234`).

## Phase 1: SQL Migration ✅ COMPLETE

**File:** `SQL/v19_id_generation.sql`

### Table: `admin.id_generation_rules`

| Column | Type | Notes |
|---|---|---|
| id | UUID PK | `DEFAULT gen_random_uuid()` |
| target_table | TEXT NOT NULL | Schema-qualified table name (e.g., `public.users`, `sim.scenarios`) |
| table_abbreviation | VARCHAR(4) NOT NULL | Admin-defined uppercase abbreviation (e.g., USR, ACC, ADR, SPT) |
| table_description | TEXT | Optional description |
| separator | VARCHAR(2) NOT NULL DEFAULT '-' | Character(s) between abbreviation and code (e.g., `-`, `*`, `.`, or empty string for none) |
| suffix | TEXT DEFAULT '' | Optional suffix appended after the code |
| letter_case | TEXT DEFAULT 'uppercase' | CHECK: uppercase/lowercase/mixed — controls case of letters in the code |
| num_letters | INTEGER DEFAULT 3 | 0–10, count of random letter characters in the code |
| num_digits | INTEGER DEFAULT 4 | 0–10, count of random digit characters in the code |
| excluded_chars | TEXT DEFAULT '' | Characters to exclude from generation (e.g., 'O0I1L' to avoid ambiguous chars) |
| seed_value | BIGINT DEFAULT 1 | Starting sequence number (for sequential fallback/collision avoidance) |
| current_sequence | BIGINT DEFAULT 0 | Last-used sequence (auto-incremented) |
| is_active | BOOLEAN DEFAULT TRUE | |
| created_by / updated_by | UUID FK → admin_users | NULL for auto-generated default rules |
| created_at / updated_at | TIMESTAMPTZ | |

**Constraints:**
- [x] `CHECK (table_abbreviation ~ '^[A-Z]{1,4}$')` — 1–4 uppercase letters only
- [x] `CHECK (num_letters >= 0 AND num_letters <= 10)`
- [x] `CHECK (num_digits >= 0 AND num_digits <= 10)`
- [x] `CHECK (num_letters + num_digits >= 1)` — code must have at least 1 character
- [x] **Partial unique index:** `UNIQUE(target_table) WHERE is_active = TRUE` — one active rule per table
- [x] **Unique index:** `UNIQUE(table_abbreviation) WHERE is_active = TRUE` — no two active rules share an abbreviation

### ID Format

The generated display ID follows this structure:

```
{table_abbreviation}{separator}{alphanumeric_code}{suffix}
```

The **alphanumeric code** is a randomly interleaved mix of letters and digits (not ordered). The positions of letters vs digits are randomized each time.

**Examples:**
| Table | Abbreviation | Separator | Letters | Digits | Excluded | Result |
|---|---|---|---|---|---|---|
| `public.users` | USR | `-` | 3 | 4 | — | `USR-6HT8GKL` |
| `admin.support_tickets` | SPT | `*` | 4 | 4 | O0I1L | `SPT*H8J43KLH` |
| `public.accounts` | ACC | `-` | 2 | 3 | — | `ACC-A8K2M` |
| `public.addresses` | ADR | `-` | 3 | 4 | — | `ADR-6HT8GKL` |
| `sim.scenarios` | SCE | `.` | 2 | 4 | — | `SCE.AB1234` |
| `sim.certificates` | CRT | (empty) | 3 | 3 | — | `CRTA8K2BM` |

### Table: `admin.generated_ids`

| Column | Type | Notes |
|---|---|---|
| id | UUID PK | |
| target_table | TEXT NOT NULL | Schema-qualified (e.g., `public.users`) |
| record_id | UUID NOT NULL | The original row's UUID |
| display_id | TEXT NOT NULL | The generated human-readable ID |
| rule_id | UUID FK → id_generation_rules | ON DELETE SET NULL |

**Unique indexes:** `(target_table, record_id)` and `(target_table, display_id)` — one display ID per record, unique within each table.
