# v17.0 — Unsaved Changes Guard (Admin app)

**Status:** COMPLETE
**Companion plan (Platform + Simulator):** `E:\project-nidus\projectplan\v750_Unsaved_Changes_Guard_Plan.md` — same feature, same API shape, built separately in the monorepo since Admin shares no code with it (`CLAUDE.md` rule 34.2/46). Read both together; this file covers only the Admin app.

## Goal

Warn the user before they leave an open record (new or edit) with unsaved changes — sidebar/breadcrumb clicks, Cancel buttons, tab close/refresh, and (best-effort) browser back/forward. Build it once as a shared primitive so every current and future form in this app gets it with one hook call, not a bespoke implementation per page.

## Investigated first — key constraint

All three apps (`shell`, and by extension every module) pin `react-router-dom ^6.30.2` and mount via plain `<BrowserRouter>` (`shell/src/App.jsx`), **not** a data router (`createBrowserRouter`/`RouterProvider`). React Router v6's official navigation-blocking API (`useBlocker`, `unstable_usePrompt`) **only works with a data router** — it throws if called under `<BrowserRouter>`. Migrating the shell (and every module federation remote's routes) to a data router is a large, invasive change and is explicitly out of scope here (see Non-goals). No existing `beforeunload`/dirty-tracking/`useBlocker` code exists anywhere in this app today — this is greenfield.

Confirmed reusable building blocks already in `packages/ui`:
- `useConfirmAction()` + `AdminModal` (`packages/ui/src/useConfirmAction.jsx`) — generic confirm-dialog hook already used for destructive actions elsewhere. Reuse this for the "Discard changes?" prompt rather than building a new modal.
- No universal form library (react-hook-form/formik) — every form is hand-rolled `useState`. Dirty-tracking must be something each page computes itself and hands to the guard, not something auto-derived from a shared form abstraction.

## Design

### `packages/shared/src/UnsavedChangesContext.jsx` (new)

- `UnsavedChangesProvider` — mounted **once**, inside `<BrowserRouter>` in `shell/src/App.jsx` (wraps the whole routed app, so it works across every federated module without each module needing its own provider).
  - Tracks a `Set` of active guard ids + their dirty flags (supports more than one mounted guard, though normally one form is open at a time) → derives a single `isDirty` boolean.
  - **`beforeunload`**: standard `window.addEventListener('beforeunload', ...)` with `e.preventDefault(); e.returnValue = ''` when dirty. Reliable regardless of router setup — covers tab close, refresh, typing a new URL. Note: modern browsers show a fixed generic message; custom text is not honoured by any current browser, so don't design copy around a custom message.
  - **In-app link clicks**: one `document.addEventListener('click', handler, true)` registered by the provider (capture phase) — finds the nearest `<a href>` ancestor of the click target; skips modified clicks (ctrl/cmd/shift/middle-click, `target="_blank"`) so "open in new tab" still works untouched; if dirty, `preventDefault()` + show the confirm modal (via `AdminModal`) + `navigate(href)` on confirm. **This one listener covers every sidebar link, breadcrumb, and "back to list" link in every module — no need to touch `AdminSidebar.jsx` or any module's own links individually.**
  - **Browser back/forward (`popstate`)**: best-effort only (see Non-goals) — re-push current path to cancel the visual back, show the same confirm modal, replay the navigation on confirm.
  - Exposes `requestNavigation(path)` for a form's own Cancel/"Back to list" button to call instead of raw `navigate(path)`.
- `useUnsavedChangesGuard(isDirty, message?)` — the one-line hook a form page calls with its own computed dirty boolean; registers/unregisters with the provider on mount/unmount/change.

### Reused, not rebuilt

- Confirm dialog UI: `AdminModal` (existing).
- No new SQL — this is purely a frontend UX guard, nothing persisted.

### Rollout scope (deliberately small)

Do **not** attempt to retrofit every existing form in this pass — unscoped, and against this repo's own "don't refactor unrelated modules" discipline. Instead:

1. Build the provider + hook (above), wire into `shell/src/App.jsx` once.
2. Pilot on **one** representative form to prove it end-to-end: `modules/admin-mgmt/src/pages/AdminUserEditPage.jsx` (already has a clear "loaded record → edited state" shape to diff for `isDirty`).
3. Add a new rule to this repo's `CLAUDE.md` (Documentation & Testing section) mandating the guard for all **new or amended** create/edit forms going forward — mirrors how project-nidus's `CLAUDE.md` already mandates export menus / row numbers / PWA for all new list & form features. Existing forms adopt it opportunistically when touched, not in a single sweep.

### Non-goals

- **Guaranteed interception of the browser Back/Forward buttons.** The `popstate` re-push trick is a known, long-standing workaround (what React Router v5's `<Prompt>` did internally) but isn't pixel-perfect on every browser/gesture (e.g. multi-step back via long-press on mobile back gesture can slip past it). The only fully-guaranteed fix is migrating `shell` (and coordinating every module's routes) to `createBrowserRouter`/`RouterProvider` so `useBlocker` can be used — a much larger, separate migration, not attempted here.
- Retrofitting every existing form immediately (see Rollout scope above).
- Anything server-side/persisted — this is a client-side UX guard only.

## Manual test checklist

1. Open `AdminUserEditPage`, change a field, click a sidebar link → confirm modal appears; **Keep editing** stays on the page with the edit intact; **Discard** navigates away.
2. Same page, dirty, close/refresh the tab → native browser "Leave site?" prompt appears.
3. Same page, dirty, click a `target="_blank"` link → opens in new tab with no prompt (guard doesn't fire).
4. Same page, not dirty → navigating away is silent, no prompt.
5. Browser back button while dirty → prompt appears (best-effort; note any browser/gesture where it doesn't, per Non-goals).
