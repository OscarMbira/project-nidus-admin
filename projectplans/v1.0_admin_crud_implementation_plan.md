## 12. Shared Infrastructure ✅

**Status:** Complete

### 12.1 Mutation Service Pattern (`packages/shared/src/mutationServices.js`) ✅
Every mutation follows this pattern:
1. Call RPC function (permission check happens server-side via `check_admin_permission()`)
2. RPC function performs the operation + inserts audit log entry
3. Return success/error to the UI
4. UI shows toast notification

```js
// Example pattern:
export async function inviteAdminUser(email, role, message, expiryHours) {
  const db = getAdminDb()
  const { data, error } = await db.rpc('invite_admin_user', {
    p_email: email,
    p_role: role,
    p_message: message,
    p_expiry_hours: expiryHours,
    p_invited_by: getCurrentAdminUserId()
  })
  return { data, error }
}
```

### SQL Design Principles
1. All mutations go through RPC functions (never direct table updates from the client)
2. Every RPC checks permissions via `admin.check_admin_permission()`
3. Every mutation logs to `admin.admin_audit_log` via `admin.log_admin_action()`
4. Functions use `SECURITY DEFINER` with explicit `SET search_path`
5. Return meaningful error messages via `RAISE EXCEPTION`
