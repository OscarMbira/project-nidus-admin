## Background & Scope

The existing `RefundListPage` at `/subscriptions/refunds` already handles **Create**, **Approve**, and **Reject**. This plan completes full CRUD by adding:

- **30-day eligibility enforcement** — refunds can only be raised against invoices paid within the last 30 days.
- **Edit** — modify reason and/or amount of a `pending` refund.
- **Cancel** — requester (or admin) cancels a `pending` refund before it is processed.
- **Process** — explicitly mark an `approved` refund as `processed` (payment issued).
- **Detail view** — dedicated page with full refund info, invoice context, and action timeline.
- **Role restrictions** tightened across all operations.
- **Sidebar access** extended to `support_admin` (read-only).

---

## 30-Day Window Rules

1. **Invoice must have `status = 'paid'`** and a non-null `paid_at`.
2. **`paid_at > NOW() - INTERVAL '30 days'`** — enforced at the DB RPC level, not just UI.
3. On the Create modal, the UI shows the days remaining (e.g., "12 days left to refund") or a hard block with an error message if the window has closed.
4. Invoices with status `cancelled`, `refunded`, `draft`, or `overdue` are excluded from the refundable invoice dropdown.

### 5.2 — Seed File Template

```sql
-- ============================================================================
-- v55: 30-Day Refund seed data
-- Prerequisites: v54_refund_30day_crud.sql, v14_subscription_seed_data.sql
-- Idempotent: fixed UUIDs + ON CONFLICT DO NOTHING
-- Run: pnpm run admin:seed-refunds
-- ============================================================================

DO $$
DECLARE
  v_admin_id UUID;
  v_invoice_id UUID;
BEGIN
  -- Resolve first active super_admin
  SELECT id INTO v_admin_id FROM admin.admin_users
    WHERE role = 'super_admin' AND status = 'active' LIMIT 1;

  -- Resolve first paid invoice (created by seed data)
  SELECT id INTO v_invoice_id FROM admin.invoices
    WHERE status = 'paid' LIMIT 1;

  IF v_invoice_id IS NULL THEN
    RAISE NOTICE 'No paid invoice found — skipping refund seed';
    RETURN;
  END IF;

  INSERT INTO admin.refunds (id, invoice_id, amount, currency, reason, status, created_by, updated_by, created_at)
  VALUES
    ('a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11'::uuid,
     v_invoice_id, 49.99, 'USD', 'Customer reported billing error — pending review.',
     'pending', v_admin_id, v_admin_id, NOW() - INTERVAL '2 days'),

    ('a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a12'::uuid,
     v_invoice_id, 29.99, 'USD', 'Duplicate charge on renewal.',
     'pending', v_admin_id, v_admin_id, NOW() - INTERVAL '5 days'),

    ('a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a13'::uuid,
     v_invoice_id, 99.00, 'USD', 'Service unavailable during subscription period.',
     'approved', v_admin_id, v_admin_id, NOW() - INTERVAL '10 days'),

    ('a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a14'::uuid,
     v_invoice_id, 149.00, 'USD', 'Accidental double payment.',
     'processed', v_admin_id, v_admin_id, NOW() - INTERVAL '20 days'),

    ('a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a15'::uuid,
     v_invoice_id, 19.99, 'USD', 'Requesting refund past eligibility window.',
     'rejected', v_admin_id, v_admin_id, NOW() - INTERVAL '25 days'),

    ('a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a16'::uuid,
     v_invoice_id, 59.99, 'USD', 'Customer changed mind — request withdrawn.',
     'cancelled', v_admin_id, v_admin_id, NOW() - INTERVAL '7 days')

  ON CONFLICT (id) DO NOTHING;

  -- Set processed_at for the processed row
  UPDATE admin.refunds SET processed_at = NOW() - INTERVAL '15 days'
    WHERE id = 'a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a14'::uuid
    AND processed_at IS NULL;

  -- Set approved_by for approved and processed rows
  UPDATE admin.refunds SET approved_by = v_admin_id
    WHERE id IN (
      'a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a13'::uuid,
      'a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a14'::uuid
    ) AND approved_by IS NULL;

  RAISE NOTICE 'v55: Refund seed data applied (6 rows).';
END $$;
```
