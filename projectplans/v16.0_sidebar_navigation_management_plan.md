# v16.0 — Sidebar Navigation Management (no-SQL rename + per-role visibility)

**Status:** COMPLETE
**Companion plan (Platform + Simulator):** `E:\project-nidus\projectplan\v749_Sidebar_Menu_Label_Rename_Plan.md` — same rename-without-SQL ask extended to the Platform/Simulator monorepo's own `public.menu_items`/`role_menu_items`. That system already has a mature per-role visibility UI (`RoleMenuCustomiser.jsx`); the only gap there, same as here, is label rename.

## Problem

The admin sidebar is already DB-driven (`admin.nav_nodes`, SQL v51/v52), but there is **no admin UI** over that table. Every rename or visibility change to date has shipped as a one-off versioned SQL file (v62, v91, v102, v106, v114, v119 rename, v120 rename). Renaming a label today means writing and running a new `SQL/vN_..._nav_rename.sql` file. This plan adds a UI so Super Admin can:

1. Rename any sidebar section / group / item label without SQL.
2. Toggle which admin roles can see each menu node (per-role visibility) and hide a node entirely, without SQL.

## Decisions locked in (confirmed with user)

- **"PMO" is a Platform-system (`E:\project-nidus\`) end-user role, not an admin-console role.** It has no bearing on this admin app's role model. `admin.nav_nodes.roles` and the visibility matrix below cover only this console's existing 4 roles: `super_admin`, `system_admin`, `support_admin`, `content_admin` (`packages/shared/src/constants.js`). No new role is created by this plan.
- **Visibility axis is role-only.** No sidebar section in this console is currently split by Platform vs. Simulator "system" — that distinction lives inside individual pages (e.g. Subscription Preview's `system=platform|simulator` query param), not at the nav level. This plan does not add a second Platform/Simulator visibility dimension to `nav_nodes`. If that's needed later it's a separate, additive change (new `system_scope` column) — noted under Non-goals.

## Current architecture (verified)

- `admin.nav_nodes` (v51): `node_key` (stable, independent of `label`), `parent_key`, `node_type` (`standalone|section|group|item`), `label`, `path`, `active_paths`, `roles TEXT[]`, `sort_order`, `is_active`, `badge`.
- `admin.list_admin_nav_nodes(p_admin_user_id)`: returns nodes where `is_active = TRUE AND (roles = '{}' OR caller's role = ANY(roles))` — this is what the live sidebar renders (`packages/shared/src/navServices.js` → `AdminSidebar.jsx`).
- `admin.upsert_nav_node(...)`: exists but is **hardcoded to `role = 'super_admin'`** (not permission-key gated like the rest of the codebase) and requires every column on every call — no frontend caller exists today. Only `scripts/generate-admin-nav-seed.js` (→ `v52`) and hand-written SQL files write to this table.
- `packages/shared/src/defaultAdminNav.js` (`DEFAULT_NAV_SECTIONS`/`DEFAULT_STANDALONE`): hardcoded fallback used only when the RPC errors or returns zero rows. `node_key` is derived from this file at generation time (stable hash, or a fixed override in `NODE_UUID_OVERRIDES`) — **renaming a `label` never changes `node_key`**, so renames are inherently non-cascading and safe.
- `modules/admin-mgmt/src/pages/RolePermissionsPage.jsx`: existing role × capability checkbox matrix (roles as columns, capabilities as rows) — this is the template to reuse for role × nav-node visibility.

## Scope

**In scope:** rename any node's `label`; toggle a node's visibility per role (edit `roles[]`); show/hide a node entirely regardless of role (`is_active`).

**Non-goals (this phase):** creating/deleting/reordering nav nodes through the UI (still SQL — `nav_nodes` already supports it structurally, but add/delete introduces `node_key`/`sort_order` collision handling that's a bigger, separable piece of work); a Platform/Simulator visibility dimension; syncing renames back into `defaultAdminNav.js` (the fallback will drift from the DB after a rename — acceptable, since it's only ever rendered when the RPC call itself fails, i.e. DB is unreachable).

## Design

### 1. Permission

Add `nav.configure` (new permission key, `admin_permissions` category `navigation`), granted to `super_admin` only initially — mirrors how `lifecycle.configure` is scoped. `admin.upsert_nav_node`'s hardcoded `role <> 'super_admin'` check gets replaced with `admin.check_admin_permission(v_admin_user_id, 'nav.configure')` for consistency with every other admin RPC in this codebase.

### 2. New RPCs (`admin` schema)

Narrow, single-purpose RPCs rather than routing UI edits through the all-fields `upsert_nav_node` (safer — a rename click can't accidentally null out `path` or `node_type` from a stale client payload):

- `admin.list_all_nav_nodes_for_management(p_admin_user_id UUID DEFAULT NULL)` — returns **every** node (active + inactive, all roles), gated on `nav.configure`, for the management screen. (Distinct from `list_admin_nav_nodes`, which is self-scoped to the caller's own visible menu.)
- `admin.rename_nav_node(p_node_key TEXT, p_label TEXT, p_admin_user_id UUID DEFAULT NULL, p_reason TEXT DEFAULT NULL) RETURNS UUID`
- `admin.set_nav_node_roles(p_node_key TEXT, p_roles TEXT[], p_admin_user_id UUID DEFAULT NULL, p_reason TEXT DEFAULT NULL) RETURNS UUID`
- `admin.set_nav_node_active(p_node_key TEXT, p_is_active BOOLEAN, p_admin_user_id UUID DEFAULT NULL, p_reason TEXT DEFAULT NULL) RETURNS UUID`

All four: permission-gated on `nav.configure`, call `admin.log_admin_action('nav_node.rename'|'.set_roles'|'.set_active', ...)` with before/after snapshots (matches every other admin RPC's audit pattern). No Record Lifecycle maker/checker gating — nav labels are low-risk/reversible, unlike pricing; can be added later the same way v118 did for `subscription_plans` if this ever needs sign-off.

### 3. Frontend

- `packages/shared/src/navServices.js`: add `fetchAllNavNodesForManagement`, `renameNavNode`, `setNavNodeRoles`, `setNavNodeActive`.
- `modules/admin-mgmt/src/pages/NavigationManagementPage.jsx` (new): flat table sorted by `sort_order`, indented by `node_type` depth (standalone/section/group/item — same tiering `AdminSidebar.jsx` already renders), columns: **Label** (inline-editable text field, save-on-blur or explicit Save), **Active** (toggle), then one checkbox column per role (`super_admin`, `system_admin`, `support_admin`, `content_admin`) — structurally identical to `RolePermissionsPage.jsx`'s matrix, including its "dirty state → single Save" pattern. Wrap mutation controls in `<PermissionGate permission="nav.configure">`.
- Route: `modules/admin-mgmt/src/index.jsx` → `<Route path="navigation-management" element={<NavigationManagementPage />} />`.
- Sidebar entry: add to `packages/shared/src/defaultAdminNav.js`, `admin-mgmt` section → `Access Control` group (next to Role Permissions):
  `{ label: 'Navigation Management', path: '/admin-mgmt/navigation-management', roles: ['super_admin'] }`

### 4. SQL (next version is **v121** — v119/v120 already exist as nav-rename one-offs)

- `SQL/v121_nav_node_management.sql` — `nav.configure` permission + grant to super_admin; replace `upsert_nav_node`'s hardcoded role check; add the 4 RPCs above.
- `SQL/v122_nav_node_management_seed_data.sql` — seed the new "Navigation Management" nav_node row itself (bootstrap problem: the page that lets you avoid hand-written nav SQL still needs one seed file to add its own menu entry). Regenerate via `scripts/generate-admin-nav-seed.js` conventions (stable id via `NODE_UUID_OVERRIDES` entry, since this node is inserted mid-tree like the v52 comment already flags for such cases) rather than hand-rolling the UUID.
- `package.json`: `admin:migrate-nav-management` / `admin:seed-nav-management` scripts.

## Manual test checklist

1. Rename a section/group/item label → reload sidebar → new label appears; `node_key`/routing unaffected.
2. Uncheck `support_admin` on a node a support_admin currently sees → log in (or impersonate) as support_admin → item is gone.
3. Toggle a node's Active off → item disappears for every role, including super_admin.
4. Attempt the RPCs as an admin without `nav.configure` → expect permission-denied.
5. Check **Audit Trail** for `nav_node.rename` / `.set_roles` / `.set_active` entries with correct before/after.
