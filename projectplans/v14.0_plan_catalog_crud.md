# v14.0 — Plan Catalog (Full CRUD for Subscription Plans)

**Status:** Complete — implementation done; Phase 6 requires live DB apply + manual verification

## Context

Over the course of fixing the Platform/Simulator pricing-page sync issues,
`public.subscription_plans` was established as the single source of truth for
pricing across both public apps (they now fetch live via
`fetchPricingCatalogBundle`, no hardcoded prices remain). Admin can already
**edit price** and **activate/deactivate** a plan via the existing
`PricingPlansPage.jsx`, but there is no facility to **create** a new plan
tier or **delete** one — no full lifecycle control over the catalog.

**Goal:** a new admin page giving true create/read/update/delete control over
the plan catalog, covering both Platform and Simulator systems, where changes
automatically reflect on both public pricing pages (already true today, since
both read live from this same table — no further wiring needed there).

This is a **new page**, separate from `PricingPlansPage.jsx` (which keeps its
existing price-change-history focus, left untouched).

## Phase 1 — Database layer

New migration `SQL/v92_subscription_plan_catalog_crud.sql`. Three `admin`-schema RPCs, following
the existing convention (`admin.sync_subscription_plan_price` /
`admin.set_subscription_plan_catalog_active` in `v81_simulator_professional_catalog_publish.sql`):
explicit `p_admin_user_id` param, permission check
`admin.check_admin_permission(p_admin_user_id, 'subscriptions.edit') OR ... 'pricing.edit'`,
`SECURITY DEFINER`, audit via `admin.log_admin_action(...)`, grants to
`authenticated, service_role`. No new permission strings needed.

- [x] `admin.create_subscription_plan(...)` — uniqueness on `(plan_type, billing_cycle, catalog_scope)`, logs `subscription_plan.create`
- [x] `admin.update_subscription_plan(...)` — identity fields immutable; price changes write `admin.pricing_change_history`; logs `subscription_plan.update`
- [x] `admin.delete_subscription_plan(...)` — hard delete with normalized subscriber safety check; logs `subscription_plan.delete`

**Apply:** `pnpm run admin:migrate-plan-catalog-crud`
