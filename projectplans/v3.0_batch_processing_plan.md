# Batch Processing & Close of Business — Full Implementation Plan

**Version:** 3.0
**Created:** 2026-06-20
**Updated:** 2026-06-20
**Status:** Complete
**Scope:** Bulk selection, import/export, background job queue, and COB processing across Admin, Platform, and Simulator systems

---

## Context

The admin panel currently supports only single-record actions — one user deactivated at a time, one ticket assigned at a time. Admins managing hundreds of records need bulk selection with action bars (like Asana/Trello), CSV import/export for offline data pipelines, a background job queue for large operations, and a full Close of Business (COB) pipeline with system date management, holiday calendar, and configurable end-of-day processes.

---

## Architecture Decision: New Module

A new federated module `batch-ops` (port 5193) houses Batch Jobs and COB pages. Bulk selection and import/export are shared capabilities in `packages/ui` and `packages/shared` that enhance existing list pages across all modules. This follows the existing module federation pattern.

**File:** `packages/ui/src/ProgressIndicator.jsx` (new)

Progress bar with label, current/total count, and percentage display.

### 1.5 useBulkSelection Hook

**File:** `packages/shared/src/useBulkSelection.jsx` (new)

Reusable hook encapsulating bulk selection lifecycle:

```
useBulkSelection({ rows, idKey }) → {
  selectedIds, setSelectedIds, selectedItems,
  processing, progress, results,
  executeBulk(operation, { signal }),
  clearSelection
}
```

- Syncs selection with row changes (removes stale IDs)
- Sequential execution with per-item progress callbacks
- AbortSignal support for cancellation
- Auto-clears selection after completion

### 1.6 Bulk Operation Engine

**File:** `packages/shared/src/bulkOperationService.js` (new)

```
executeBulkOperation({ items, operation, onProgress, signal })
  → { succeeded, failed, errors[] }
```

Iterates items sequentially, calls `operation(item)` for each, tracks results, respects cancellation.

### 3.2 Batch RPC Functions

| Function | Returns | Permission | Description |
|---|---|---|---|
| `create_batch_job(...)` | UUID | `batch.jobs.create` | Creates job + items from record ID array |
| `process_batch_job_chunk(job_id, chunk_size)` | TABLE | — | Returns next chunk of pending items, marks as processing |
| `update_batch_job_item(job_id, item_id, status, error)` | BOOLEAN | — | Updates item, atomically increments job counters |
| `complete_batch_job(job_id)` | BOOLEAN | — | Finalizes job status from item outcomes |
| `cancel_batch_job(job_id)` | BOOLEAN | `batch.jobs.cancel` | Cancels job, skips remaining items |
| `get_batch_jobs(...)` | TABLE | `batch.jobs.view` | List jobs with pagination |
| `get_batch_job_detail(job_id)` | JSONB | `batch.jobs.view` | Job + items detail |

### 3.3 Processing Approach

Client-side sequential processing via `executeBulkOperation`. Each item calls the existing single-record RPC function, ensuring per-record permission checks and audit logging. The `batch_jobs` table provides persistence so admins can navigate away and check back.

For large batches, `process_batch_job_chunk` enables chunked processing with progress persisted in the database.

| Order | Process Key | Name | Target | RPC Function |
|---|---|---|---|---|
| 10 | `expire_subscriptions` | Expire Overdue Subscriptions | all | `admin.cob_expire_subscriptions` |
| 20 | `close_resolved_tickets` | Close Resolved Tickets | admin | `admin.cob_close_resolved_tickets` |
| 30 | `archive_old_errors` | Archive Old Errors | admin | `admin.cob_archive_old_errors` |
| 40 | `generate_daily_summary` | Generate Daily Summary | all | `admin.cob_generate_daily_summary` |
| 50 | `reset_daily_counters` | Reset Daily Counters | all | `admin.cob_reset_daily_counters` |

| 80 | `generate_cob_report` | Generate COB Report | all | `admin.cob_generate_report` |

Each process is an independent RPC function returning a JSONB result summary. Admins can reorder, enable/disable, and configure parameters.

### 4.4 COB RPC Functions

**Management functions:**

| Function | Returns | Permission | Description |
|---|---|---|---|
| `get_current_business_date()` | DATE | — | Reads from system_settings |
| `advance_business_date(admin_id)` | DATE | `cob.run.execute` | Finds next working day via business_calendar, updates setting |
| `start_cob_run(date, trigger_type, admin_id)` | UUID | `cob.run.execute` | Creates run + steps, sets lock |
| `execute_cob_step(run_id, step_id, admin_id)` | JSONB | `cob.run.execute` | Calls the step's RPC function dynamically |
| `cancel_cob_run(run_id, admin_id)` | BOOLEAN | `cob.run.cancel` | Cancels remaining steps, releases lock |
| `get_cob_runs(limit, offset)` | TABLE | `cob.run.view` | List runs with pagination |
| `get_cob_run_detail(run_id)` | JSONB | `cob.run.view` | Run + steps detail |
| `upsert_calendar_entry(...)` | UUID | `cob.calendar.edit` | Add/update calendar entry |
| `delete_calendar_entry(date)` | BOOLEAN | `cob.calendar.edit` | Remove calendar entry |

| `update_cob_process(id, updates)` | BOOLEAN | `cob.processes.edit` | Update process config/order |

**Individual COB process functions** (each takes `p_business_date DATE, p_params JSONB`, returns JSONB summary):

| Function | Description |
|---|---|
| `cob_expire_subscriptions` | Cancel active subscriptions past expiry date |
| `cob_close_resolved_tickets` | Auto-close resolved tickets older than X days (configurable) |
| `cob_archive_old_errors` | Archive resolved error_aggregations older than threshold |
| `cob_generate_daily_summary` | Aggregate counts from audit_log, support_tickets, etc. |
| `cob_reset_daily_counters` | Reset daily rate limits/counters (placeholder for future) |
| `cob_lock_business_day` | Set lock flag in system_settings |
| `cob_advance_business_date` | Move system date to next working day |
| `cob_generate_report` | Aggregate all step results into COB report JSONB |

### 4.5 COB Trigger Mechanism

- **Manual:** Super admin clicks "Run COB" on the COB Dashboard
- **Scheduled:** pg_cron or Supabase cron calls `start_cob_run` at `cob.auto_run_time` daily (if `cob.auto_run_enabled = true`)
- **Pre-COB validation:** Checks that no COB is already running, the date hasn't already been closed
- **COB lock:** `cob.lock_active = true` during processing, prevents concurrent operations
- **Resilience:** If browser closes mid-COB, run state is persisted in DB — admin can resume or cancel
